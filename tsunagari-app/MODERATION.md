# 投稿・返信の管理

管理者でログインし、自分のプロフィール → **投稿管理** を開きます。各投稿・返信の「管理」から、その項目を直接開くこともできます。

## 通報と管理操作

| 操作 | 利用できる人 | 動作 |
| --- | --- | --- |
| 通報 | ログインしたメンバー | 投稿・返信の「通報」から理由と補足を送信 |
| 通報一覧 | 管理者 | 通報者・理由・対象を確認し、対応理由を記録 |
| 非表示・再表示 | 管理者 | 理由を必須として、表示を切り替える |
| 完全削除 | 管理者 | 理由と削除確認を必須として、投稿・返信を削除 |
| 操作履歴 | 管理者 | 操作者・日時・対象ID・理由を確認 |
| 保存期間 | 管理者 | 無期限、30・90・180・365・730日から選択 |

通報者の名前と補足は管理者にだけ表示します。通報だけで自動的に非表示にはしません。同じ人から同じ項目への通報は1回まで、新しい通報は1日20件までです。「対応済みにする」は対応記録だけを更新します。非表示・削除は別途操作してください。

投稿・返信一覧は、本文・投稿者名の検索、表示状態の絞り込み、25件ごとのページ移動に対応しています。一般メンバーは管理画面・管理APIを利用できません。

非表示の投稿は通常の一覧・検索・投稿件数から除外します。一般メンバーはその投稿の返信・画像・動画の直接URLも閲覧できません。管理者は管理画面で内容を確認し、再表示できます。非表示の返信はコメント一覧・件数から除外します。親投稿が非表示の場合、返信だけ再表示しても一般メンバーには見えません。

投稿を完全削除すると、配下の返信・いいね・添付ファイルも削除します。返信の削除は、その返信だけが対象です。一般メンバーは従来どおり自分の投稿・返信だけ削除できます。作者による削除も操作履歴に残ります。

## 保存期間と自動削除

**初期設定は無期限です。更新するだけでは既存の投稿を自動削除しません。**

期間を選ぶと、現在の削除対象件数を表示します。「保存期間を変更」で理由と確認を入力し、実行すると設定を保存します。期間は投稿・返信の作成日時から数え、非表示の内容も対象です。古い投稿を削除する場合、その投稿に最近付いた返信も一緒に削除します。

Node.jsサーバーの起動時と稼働中の約5分ごとに処理します。1回につき古い投稿50件・独立した古い返信50件まで順に削除するため、件数が多い場合は時間がかかります。停止中は動作せず、次の起動時に再開します。「無期限」に戻すと以後の期間による削除を停止しますが、すでに削除した内容は戻りません。

添付ファイルを削除できなかった場合、削除待ち記録をDBに保存し、次の処理で再試行します。元の投稿が削除されていれば、削除待ちの添付もAPIから閲覧できません。

この自動処理は `server.mjs` で起動するNode.js版に対応しています。Cloudflare Workersへの直接配置では別途スケジュール実行が必要なため、期間指定の設定は受け付けません。

## 記録と反映範囲

- 操作履歴・通報記録は投稿削除後も残します。削除された投稿・返信本文のコピーは保存しません。ただし、管理者や通報者が理由・補足に記載した内容は記録に残ります。
- この保存期間は、アカウント、プロフィール、予定、固定コメント、操作履歴、通報記録、別途作成したバックアップには適用しません。
- 非表示・削除時は対象の未配信通知を取り消します。送信直前にも表示状態を確認します。すでに配信済み・送信中の通知や、利用者がすでに表示・保存した内容は回収できません。
- ほかの利用者が開いている画面は、更新時に変更が反映されます。
- 操作履歴はSNSの画面から編集・削除できませんが、DBを直接変更できるサーバー管理者に対する改ざん防止機能ではありません。

## 更新手順

1. 起動画面で `Ctrl+C` を押してSNSを停止します。
2. 現在の `data-external-trial` フォルダーを丸ごとバックアップします。保存先を変更している場合は、その保存先を使います。
3. GitHubの更新版の `tsunagari-app` 内を、これまで使っているアプリフォルダーに上書きします。`data-external-trial` と `.sns-private` は残してください。
4. `start-sns.cmd` で再起動し、ブラウザー・ホーム画面アプリを開き直します。
5. 管理者でプロフィール →「投稿管理」を開きます。

Node.js版は `drizzle/0007_moderation.sql` を自動適用し、既存のアカウント・投稿・返信を引き継ぎます。Cloudflare D1に直接配置している場合は、未適用のマイグレーションを番号順に適用してください。

## 検証

自動テストでは、管理者権限・通報の検証・非表示後の検索と添付のアクセス制御・完全削除・添付削除の再試行・保存期間・既存DBからの更新・通知の取消・画面の文字エスケープとログアウト後の応答破棄を確認します。ブラウザーの外観とiPhone実機の操作は未確認です。
