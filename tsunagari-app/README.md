# つながり — 社内SNS

ChatGPTアカウントを使わず、**専用のログインIDとパスワード**で利用します。招待された社員だけが登録でき、未ログインでは投稿・画像・プロフィールを取得できません。文字・画像投稿、いいね、コメント、検索、iPhoneのホーム画面追加に対応。リポスト・DMはありません。

## 短い動画とアプリ通知

投稿欄の「動画」からMP4を1本（60秒以内・20MB以内）投稿し、タイムラインで再生できます。写真・スタンプとは別の投稿にします。

iPhoneではSafariからホーム画面に追加し、プロフィール →「通知設定」から通知をオンにできます。iOS 16.4以降が必要です。ほかのメンバーの新規投稿、自分の投稿への返信、固定コメントの更新が通知対象です。通知には投稿者の名前と本文の冒頭100文字、画像・動画の添付情報を表示します。投稿・返信の通知を押すと対象の投稿へ移動します。既存の端末は通知設定で「通知をオンにする」を押して登録を更新してください。設定条件・更新手順・検証範囲は [VIDEO_NOTIFICATIONS.md](VIDEO_NOTIFICATIONS.md) を参照してください。

## 固定コメント・返信の削除

ホーム上部の紹介文を、管理者が編集できる固定コメント欄に変更しました。1件・1000文字以内で、ログインしたメンバー全員に表示されます。自分の返信コメントは確認画面から削除できます。操作方法は [ADMIN_FEATURES.md](ADMIN_FEATURES.md) を参照してください。

## 共有カレンダー

PCの左メニュー、スマートフォンの下部メニューに「カレンダー」を追加しました。月ごとに予定を確認できます。予定名・日付・時刻・メモの新規登録は管理者のみ可能です。メンバー全員で共有し、編集・削除は登録者本人のみ可能です。使い方と更新手順は [CALENDAR.md](CALENDAR.md) を参照してください。

## 投稿文検索・絵文字・スタンプ

上部の検索欄から投稿本文を探して件数を確認できます。投稿欄には絵文字30種類とスタンプ6種類の選択ボタンを追加しました。写真とスタンプは合計4枚までで、スタンプだけでも投稿できます。使い方と更新手順は [SEARCH_STICKERS.md](SEARCH_STICKERS.md) を参照してください。

## 利用の流れ

1. 運用担当者がサーバーの初期設定コードを設定する。
2. 最初の利用者がそのコードを使い、管理者アカウントを登録する。
3. 管理者がプロフィール →「メンバー管理」で社員のログインIDを指定して招待コードを発行する。
4. 社員が「招待コードをお持ちの方はこちら」から表示名・ID・パスワード・招待コードを入力して登録する。
5. 2回目以降はID・パスワードでログインする。ChatGPTとの連携は不要。

招待コードは指定ID専用・1回限り・7日間有効です。管理者は利用停止・再開もできます。停止すると既存セッションも無効化します。

## 自分のPCから社外へ公開する

固定URLで起動する手順は [FIXED_URL.md](FIXED_URL.md) を参照してください。ngrokの無料アカウントに割り当てられるURLとAuthtokenを `setup-fixed-url.cmd` で一度設定し、その後は `start-sns.cmd` をダブルクリックします。同じURLを毎回使い、既存の `data-external-trial` にあるID・投稿・画像・予定を引き継ぎます。無料プランの案内ページ・通信量上限があります。初回の管理者登録と従来の一時URLは [HOME_SERVER.md](HOME_SERVER.md) を参照してください。

## ローカルで起動する（Windows / Node.js 24以上）

このフォルダでPowerShellを開きます。npm installは不要です。

```powershell
node build.mjs
node --test tests.mjs auth-tests.mjs storage-tests.mjs
$env:ADMIN_SETUP_TOKEN = Read-Host '自分だけが知っている初期設定コードを32文字以上で設定'
node server.mjs
```

`http://127.0.0.1:5173` を開き、先ほど設定したコードで最初の管理者を登録します。サーバーは初期設定コードを画面やログに出しません。未設定・32文字未満では最初の登録を受け付けません。管理者登録後はコードを環境から削除して構いません。

データは `data/sns.sqlite`、写真は `data/media/` に保存され、再起動後も残ります。`data/` を公開・Git登録しないでください。バックアップは停止中にフォルダ一式を取得してください。

`node preview.mjs` はメモリ上の一時データで動く開発用サーバーです。利用する社員データには `node server.mjs` を使います。

## 社員向けの公開

Render向けの具体的な設定と残り作業は [WEB_DEPLOY.md](WEB_DEPLOY.md) を参照してください。

このZIPはまだ公開済みサービスではありません。社内サーバーまたはクラウドへ配置する作業が必要です。

独立したNode.jsサーバーとして動かせるため、ChatGPTのホスティングは必須ではありません。HTTPSのリバースプロキシ配下で、次を設定します。

| 設定 | 内容 |
|---|---|
| `PUBLIC_ORIGIN` | 例：`https://sns.example.co.jp`。実際のHTTPSオリジンを指定。末尾スラッシュなし |
| `ADMIN_SETUP_TOKEN` | 初回のみ、32文字以上の秘密のコード |
| `DATA_DIRECTORY` | 永続ディスク上のデータ保存先。既定は `data` |
| `PORT` | 内部待受ポート。既定5173 |
| `HOST` | 既定127.0.0.1。コンテナ等で必要な場合だけ変更 |

本番CookieはSecure / HttpOnly / SameSite=Laxです。ローカルHTTP用Cookieは別名で、本番モードでは受け付けません。Nodeサーバーはクライアントから来たIP識別ヘッダーを信頼せず、直近の接続元を使います。プロキシ配下ではログインのIP別制限を複数社員で共有するため、本番導入時に信頼済みプロキシの構成と利用人数に合わせて調整してください。

Cloudflare Workers向けの `dist/server/index.js` も生成します。Node互換モード、D1 (`DB`)、R2 (`BUCKET`)、SQLマイグレーション3本が必要です。scryptの負荷を扱えるCPU予算と実環境での検証が必要です。Sitesで動かす場合は、アプリ側の認証が動くことを確認したうえでホスティング入口のChatGPT認証を外す必要があります。既存の未公開Siteのアクセス設定は変更していません。

自分のアイコン →「プロフィールを編集」で、表示名・自己紹介・場所・アイコン・ヘッダー画像を編集できます。部署欄はありません。詳しい条件と更新手順は [PROFILE_UPDATE.md](PROFILE_UPDATE.md) を参照してください。

## iPhone

公開後のHTTPSページをSafariで開き、共有 →「ホーム画面に追加」。オンラインで使用します。パスワード変更で他の端末からもログアウトします。

## 認証の実装

- パスワード12〜128文字。ソルト付きscrypt（N=16384、r=8、p=5）で保存
- セッションはランダム256ビット。有効期限7日。DBにはトークンのハッシュのみ保存
- 招待コードもDBにはハッシュのみ保存。初期管理者と招待コードの同時使用をDB制約で制御
- ログイン試行回数をID・接続元ごとに制限
- 更新APIは同一オリジン検証、全データAPI・画像配信は独自セッション検証
- ChatGPTの認証ヘッダーは本人確認に使わない
- パスワード変更・利用停止で既存セッションを失効
- 投稿や画像をService Workerへキャッシュしない

参考：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Cloudflare node:crypto](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/)。

## 検証済み・残っていること

Node.js上の自動テストで、登録・ログイン・招待コードの不正利用防止・CSRF拒否・期限切れ・試行制限・ログアウト・パスワード変更・利用停止・投稿権限・画像・再起動後の永続化を確認しています。

ブラウザー操作・iPhone実機・本番環境での負荷と動作の確認は未実施です。パスワードを忘れた場合のセルフリセット、メール送信、SSO、2要素認証、通報機能、管理者による投稿削除は未実装です。実際の社員利用を始める前に、アカウント復旧の運用を決めてください。
